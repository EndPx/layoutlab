# Human motion admission review (isolated draft)

No production integration is claimed. Run from repository root:

```
node node_modules/typescript/bin/tsc -p packages/simulation/motion-draft/tsconfig.json
node packages/simulation/motion-draft/check.mjs
```

Synthetic kinematics use mm, ms, mm/ms speed, mm/ms² acceleration and radians/ms angular speed. Each exact route edge accelerates from rest and brakes to rest, waits 100ms, then turns at bounded angular speed. Initial and target headings are explicit; heading zero faces +Z. Evaluation derives position, speed, heading and distance-based 1201mm gait cycle from one engine-relative clock. No corner smoothing, endpoint displacement or teleport is applied. This deliberately stops at every supplied vertex, including collinear vertices; route simplification would require a separately reviewed geometry-preserving rule.

Independent literal oracle: 250mm triangular travel at a=d=.001 has two 125mm halves, peak .5mm/ms and total 1000ms. 4000mm has 500mm acceleration, 3000mm cruise, 500mm braking and total 5000ms. Existing constant-speed engine at 1000mm/s gives 250ms and 4000ms respectively, excluding new stops and turns. Existing event timings cannot be retained.

The measured 749x2028 / 749x2178 push and 1397x1220 side bounds come from R2a; load is assumed wholly within cart footprint, overhanging cargo is unsupported. Crucially R2a's 1181/1252/1028 radii are about the combined rectangle center. Engine routes use CART center: push rear extent is length minus 610mm. Draft radii conservatively cover that offset plus 100mm margin; side assumes outer side extent 1057mm. See machine evidence for resulting radii. Using the smaller recentered disc without shifting the route origin would understate turning sweep.

Admission uses a full orientation-independent disc swept along each exact segment and at all stopped/turn centers, against walls, racks, resources supplied as obstacle rectangles and stopped agents. Expanded AABB corner checks overreject relative to exact circular Minkowski sums; no successful result relies on sampling. Microcases cover clear admission, corner rejection, stopped occupancy and turn contact. Moving-vs-moving reservations are not implemented.

Canonical diagnostic preserves fixture bytes and uses accepted dist exports for navigation. It explicitly enumerates 44 operational destinations: storage approach points (not storage anchors), resource service and queue slots, and unit parking. Resource IDs and canonical rack/obstacle IDs are retained. Across three profiles this gives 132 pose checks and 792 route checks; 91 poses reject. Routes separately report static admission and admission with all OTHER units parked under the same caller profile; own origin never selfblocks. This is a declared homogeneous-profile assumption, not moving traffic safety. Canonical cart-planned route geometry is assessed unchanged. Exact blockers are listed in admission.json. Conservative disc/AABB rejection does not establish full geometric impossibility.

Validation correction: original baseline has ten assertions, not eight. Revised checks.json records ten baseline assertions and 56 named regression assertions (66 total), including asymmetric 900mm acceleration/braking = 1650ms, NaN/infinities/negative inputs, degenerate rectangles, zero limits, stationary duplicate points and mutation of source limits/points, exposed phase data and returned poses. Helpers reject malformed numeric inputs by throwing before admission can return accepted. Coordinates are nonnegative and finite with magnitude at most 1e12; positive numeric parameters are bounded to [1e-12,1e12]. Zero-distance ramps are stationary; zero stop duration is currently unsupported. Trajectory clones source points and limits, and phase access returns a detached deep copy. Defaults and declared profile dimensions are frozen. This remains synthetic bounded kinematics, not calibrated physics.

Next integration gate: review exact operational destinations and profile coupling offsets; choose either revised equipment/worker coupling proven by measurements, orientation-aware polygon admission with bounded turn maneuver feasibility, or an explicitly approved layout change. Never shrink rendered humans or silently widen fixture aisles. Current disc rejection is sufficient to block naive attachment but does not prove no orientation-aware solution exists.

Proposed production contract: version engine and replay implementation together; persist motion profile version, route points, cart-origin coupling, initial/target heading, speed/acceleration/braking/angular limits, stop duration, start engine timestamp and stride length. Reserve swept geometry and time windows before motion; reject conflicts with walls/racks/resources/stopped and moving actors. Schedule arrival from new trajectory duration with explicit integer event rounding while evaluating the continuous trajectory against that scheduled contract; handling/ledger commits remain authoritative. Replay must recompute identical trajectory and admission. Renderer consumes evaluated pose/distance/task state only; task animation is a subsequent gate.

Walk_Carry remains a proxy, not a validated push/grip pose. In-place clips and distance phase do not establish footplant, handle grip, calibrated biomechanics or rigid-body physics. No new assets, rig visualization, shared dist rebuild, main files, dependencies, commits or deployments were needed.

## R2c heading-aware static draft (not production admission)

Compile with the same isolated tsconfig, then run `node packages/simulation/motion-draft/oriented-check.mjs`. Run the original `check.mjs` separately for the 66 prior assertions. New sources are oriented.ts and oriented-check.mjs; evidence is evidence/sanitized/r2-motion-next. The original disc helper and comparison remain unchanged.

Local X is right, local Z forward, root is CART center. Push350 has left/right374.5, front610, rear1418mm; push500 rear1568mm. Side assumes worker on cart RIGHT: left340, right1057, front/rear610mm. This coupling is a conservative measured bounding-box assumption, not independently established hand contact or IK. All bodies add100mm to EACH rectangle side. Square-expanded rectangle corners are more conservative than a100mm radial margin and can extend beyond the older radial-margin disc: those models differ at corners. Overhanging loads remain unsupported.

Stationary admission transforms all four local corners. Fixed-heading translation takes the convex hull of the start and end footprints: this is the continuous swept convex body, tested against rack/resource AABBs and stopped-worker oriented rectangles by separating axes. Contact rejects, with a small outward numerical tolerance. The trajectory is the existing exact supplied polyline with stop-and-turn phases; no new pathfinder, shortening or smoothing is used.

Stationary turns use the signed shortest angular phase actually emitted by trajectory. For each local corner, world X and Z are sinusoidal linear combinations; endpoints AND every derivative-zero angle within the entire arc are evaluated. Their extrema form a certified conservative full-arc AABB. This cannot miss an obstruction between angular samples; no temporal/angular samples establish admission. AABB collisions at turns can falsely reject empty portions of the actual swept shape, and are marked conservative per phase. Replacing this with exact swept-sector geometry is a future precision improvement, not a prerequisite to reject unsafe attachment. Heading magnitude beyond100pi and arcs beyond2pi are explicitly unsupported and throw. Generic body/point/room/obstacle inputs are validated and the underlying trajectory snapshots points/limits; no mutable trajectory authority is returned.

Canonical diagnosis retains44 actual destinations and canonical obstacle/resource identifiers. Storage facing direction is geometrically inferred toward rack center and recorded, NOT engine sourced. Every initial and target cardinal heading pair is tested on each available engine route; service/queue/parking have no asserted preferred yaw. Other parked workers use the same caller body profile and +Z yaw as a declared assumption; own parking origin is excluded. Pose-clear, complete-route-clear including turns, and route-clear with those stopped workers are separate fields. These are static witnesses only, not feasible moving traffic schedules. Exact named blockers and per-phase rejection attribution are in admission.json. Disc rejection alone no longer implies oriented infeasibility; neither form of conservative rejection proves no alternate maneuver or route exists.

Production gate still requires explicit engine-owned worker/cart coupling, destination headings, loading envelope and maneuver rules; versioned limits and exact trajectory timestamps; continuous space-time reservations including moving workers and handling occupancy; independent replay of the same geometry/timing; and renderer/task animation consuming committed engine state. Positive isolated witnesses do not authorize attaching a human to the main operational cart paths. Asset proportions, footplant, grip and Walk_Carry proxy limits are unchanged.
