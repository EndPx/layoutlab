# Agent initial placement review

The executable source exports AgentInitialPlacementProposal, applyAgentInitialPlacement, runAgentPlacementComparison and verifyAgentPlacementComparison. The proposal is strict AGENT_INITIAL_PLACEMENT with one existing mobile-unit ID, parent scenario ID/content hash/schema/engine and absolute or delta X/Z target. Separate approved constraints supply allowed/locked IDs, integer snap, moved-entity and Chebyshev translation budgets; model fields cannot grant authority. Unknown IDs and extra proposal fields reject. The pure transform is a primitive; comparison is the authority/admission gate and must pass before adopting a new scenario.

Only the selected existing mobileUnit.parkingSlotMm X/Z changes. Worker IDs/count/roles, declared CART footprints, speed/carry/handling, inventory/workload, seed, service/resources and geometry remain cloned from the parent. The entire comparison input is copied synchronously before its first await. Returned target transform coordinates are detached from candidate coordinates. An existing controller is never supplied to or modified by this API: applying placement creates a new initial scenario, not a live teleport.

Both baseline and candidate use geometryAccessIssuesFor plus actual createOperationsController admission for quantities, constraints, static footprint clearance and required destinations. Pairwise initial occupancy uses production navigation footprintRadiusMm and production traffic discsConflict (inclusive contact). This checks the currently declared CART footprint; it does not establish human-plus-cart safety. Geometry-proven physical coverage retains exact blocker IDs (tested R1 and OB-PACK1); resource obstruction here is its declared OB-PACK1 physical obstacle. Unprovable engine failures retain original text without inventing a blocker identity.

The distinct layoutlab.agent-placement-comparison/1 report includes canonical scenario/config/proposal/authority, parent hash, versions, affected positions and changed paths, baseline/candidate issues, runs, scope, metrics, delta and classification. Verification recomputes keylessly and compares the complete canonical export, rejecting missing/extra/tampered fields. Invalid baseline repaired by placement is candidate-only-repaired with no comparative delta or improvement claim; persisting candidate errors prevent candidate measurement. Existing station/rack report formats are untouched.
