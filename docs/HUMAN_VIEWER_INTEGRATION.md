# Human integration in the main warehouse viewer

OperationsView renders source-sized frozen workwear-v2 workers for existing picker and putaway units. The source glTF is cached once per page; each worker uses an independent SkeletonUtils clone. Source body, clothes, boots, skeleton dimensions and materials are preserved. Human source/pose/gait failure is visible while cart operations remain available; failed source requests can retry after a scene change. Owned cloned skeletons are disposed without disposing shared source geometry/materials.

The production main-pose-v1.json contains only feasible root/bone transforms, recorded vector and source SHA256. main-gait-v1.json bakes the existing source-length forward leg/arm driver over the stable-crouch two-step 0.5..1.0 m interval. Its stride is 0.5 m, with 101 samples, 12 joint rotations and 65 mm root crouch. Arm correction keeps accepted hand targets fixed. Normalized seam error is 4.2146848510894035e-8 rad. No optimizer or IK executes on render frames. Reproduce from committed inputs with `node apps/web/src/lib/humanBake.mjs`; it uses the local humanBakeDriver.mjs copy and production source/pose files and writes driver/source/pose hashes into the packet.

Animation samples absolute distance and heading from read-only retained timed segments and snapshot clock. Snapshot frequency, repeated frames and speed controls do not accumulate gait state. Waits use a grounded stopped stance; Pause freezes the same actual bones and Reset deterministically restores initial pose. History is grouped once per update, and bone diagnostics are bounded by fixed unit/joint counts. Source forward is -Z: shared PI aligns it to engine heading 0 (+Z), then engine heading rotates the entire cart/worker/tote assembly. Pooled cargo uses the identical yaw for normalized dock/cell offsets and cargo orientation; normalization is applied once. Engine x/z anchors remain exact. The initial no-history pose retains the historical canonical cart orientation.

Heading changes are instantaneous visualization; there is no added turn duration, path planning, inventory transfer, worker teleport or independent worker trajectory. Archived implementations without segment telemetry show stable stopped worker animation and disclose that limitation. Existing traffic clearance uses cart footprints, not human-body reservations; body collision safety and calibrated kinematics remain unqualified. World-space cargo AABBs now rotate with the assembly: declared object dimensions stay unchanged while world width/depth can swap at cardinal turns. Historical zero-yaw helper assertions remain unchanged.

Release evidence is in evidence/sanitized/human-main-viewer/release/. Focused tests cover actual skinned workwear boots/hand stability, independent skeletons/shared geometry, repeated sample/reset/long-route cycle, waits and cardinal headings, and cargo relative-frame/dimension invariants. Actual source-skin calibration measured minimum bootY=-0.0003091945069587862m and maximum hand drift 4.0285392358257143e-8 m over 101 samples. These are sampled rig checks, not collision certification.

The release browser tests use installed Edge at 1440 px and 390 px and a real local API built with explicit empty-key configuration; no .env is read and no model call is made. The API recipe is `node --input-type=module -e "import {createApp} from './apps/api/dist/server.js'; import {loadConfig} from './apps/api/dist/config.js'; const config=loadConfig({MODEL_API_KEY:'',API_HOST:'127.0.0.1',API_PORT:'3001'});createApp({config}).app.listen(3001,'127.0.0.1');"` from root. See the release REPORT for exact commands, outcomes, screenshots/videos, asset loads and measured CPU update cost. Existing Three shadow-map deprecation and Vite large-bundle warnings are disclosed; no FPS or body-clearance claim is made.
