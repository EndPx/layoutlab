# Gater provider G1 review

G1 implements server configuration aliases and a deliberate Gater Chat Completions payload branch only. It is not end-to-end Gater integration or live compatibility evidence.

MODEL_API_BASE_URL and MODEL_ID take precedence over legacy META_API_BASE_URL and META_MODEL_ID. MODEL_API_KEY remains server-only. Exact HTTPS api.gater.ai.id /v1 is classified as gater; official Meta with default HTTPS port remains meta. Userinfo, query/hash, nondefault remote ports, suffix hosts and extra remote paths are rejected. Loopback HTTP/HTTPS fixtures retain arbitrary local ports. No env loader or startup path changed: .env.gater.local remains explicitly opt-in; use loadEnvFileInto only in an intentional private launcher, never add automatic startup loading.

Gater payload uses system/user messages, max_tokens=2000, stream=false and the existing strict json_schema response_format. It omits Meta reasoning_effort and max_completion_tokens. These fields are an explicit candidate OpenAI-compatible payload, not verified Gater support: schema support, GLM reasoning behavior and whether reasoning shares the output cap remain unknown. An upstream rejection fails without retry; parsed JSON and existing caller domain validation remain required. No generic JSON Schema validator was added to this transport, which historically parses JSON and delegates domain schema validation to callers. G1 tests reject invalid structured JSON and missing content; caller domain-schema rejection needs G2 lifecycle coverage.

Verification: npx vitest run apps/api/test/gater-provider.test.ts passed 4 tests; npx tsc --noEmit -p apps/api/tsconfig.json passed with no downstream compile errors. git diff --check passed (an unrelated existing evidence file produced a line-ending warning). Tests inject fake fetch functions: zero remote requests, no credentials read, no inference, no money/ledger changes, no shared build. Tests cover origin confusion, aliases, config provenance, payload/call count, response parsing, redaction, pre-abort, prompt and response caps. Existing run request/deadline accounting was preserved.

Remaining G2 API callers/surfaces: apps/api/src/runs.ts, server.ts, index.ts, operations-api.ts, operations-investigations.ts, layout-investigations.ts, benchmark.ts. Audit generationSettingsOf consumers: it now records Gater reasoning as not-specified while retaining historical Meta/fixture low. Broader lifecycle paths may still reject or mislabel Gater despite passing typecheck; do not enable public runtime based on G1.

Remaining G3 web surfaces: apps/web/src/lib/api.ts, experiments.ts, export.ts, App.tsx, components/RightPanel.tsx, ExperimentsPanel.tsx, WarehouseAssistant.tsx, WarehouseWorkspace.tsx, plus associated tests and historical report replay. Extend provider unions, parsers, generation/provenance labels, status and report accounting, preserving historical Meta/fixture evidence. Lifecycle fixture tests, web checks and any explicitly authorized live validation remain later gates; pricing and structured-output compatibility remain unverified.


G2-settings correction: generationSettingsOf returns literal `not-specified` for Gater because no reasoning_effort is sent; this does not claim reasoning is disabled. The existing core schema accepts a nonempty string, and API consumers typecheck with the widened union. Historical Meta/fixture metadata stays literal `low`. The historical maxCompletionTokens metadata field remains the server output allowance (2000); the candidate Gater payload sends max_tokens while Meta/fixture send max_completion_tokens. Neither Gater strict json_schema acceptance nor reasoning consumption of this allowance has been verified upstream.

Fetch exceptions now retain a bounded uppercase classification code and valid HTTP status while redacting the message; original cause and arbitrary properties are discarded. Focused offline assertions cover both remote endpoint confusion variants, neutral-over-legacy alias precedence, literal reasoning metadata, and the Gater output cap. Config status serialization is owned by callers and was not changed here; ApiConfig itself is private and contains the key, so it must never be serialized as status wholesale.

Exact G2-settings verification: `npx vitest run apps/api/test/gater-provider.test.ts` passed 5 tests (1 file); `npx tsc --noEmit -p apps/api/tsconfig.json` exited 0 with no diagnostics. No remote calls, shared-package build, budget changes, commit or deploy were performed. Broader lifecycle validation belongs to the parallel layout worker.
